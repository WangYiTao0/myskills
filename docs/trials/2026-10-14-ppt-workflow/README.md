# #35 端到端试跑：打磨 → 生成 → AI 审核 → 人审核（2026-10-14 / 15）

全部内容虚构。用户扮演汇报人，主会话按 ppt-grill / milwaukee-ppt / ppt-review 执行。

## 文件
- `试点总结.md`、`周报摘录.md`、`数据.csv`：虚构资料（含一处可用率口径冲突，无图片）
- `简报.md`：ppt-grill 定稿简报（4 轮问答，用户全部采纳推荐答案）
- `deck.md` / `deck.pptx`：第 2 轮后的文稿与成稿；`deck-round1.pptx`：第 1 轮成稿

## 过程
1. 打磨：4 轮（观众与场合 + 口径冲突 → 核心结论 + 业务量可比性 → 页序 + 推广申请 → 逐页内容 + 预判问答），简报无待定后用户确认定稿。
2. 生成：写 md 时发现两处需同步简报（table 页需要结论行；第 1 页 `!` 未定），先改简报再生成。生成器无警告。
3. AI 审核第 1 轮：脚本 `REVIEW OK`，核对清单 9 条通过（第 9 条不适用）；第 6 条（问题页 `!` 给风险最高项）与第 1 条（`!` 支撑本页结论）在第 1 页冲突，列为未解决项。
4. 人审核：用户评价"很普通"。第 2 轮只改 md（补 stats 解读、流程说明、表格行），仍 `REVIEW OK`，观感提升有限。
5. 原型：三个视觉方向（A 保留红条撑满 / B 薄红条 / C 结论前置），用户选 **C**（只在通用 / 项目模式生效，月报保持原红条）。原型在分支 `prototype/ppt-visual-directions`。

## 发现（要改 skill 的点）
- 生成器视觉偏素：红条过重、卡片矮字小、表格贴顶、无视觉锚点 → 方向 C 落进生成器（待 to-spec）。
- 选 C 后"红条结论"变成 lead，必须是结论句，不能是口径限定（如"6 月、9 月作业量相近"）→ ppt-grill 简报字段与 ppt-review 清单要跟着改。
- 审核对后处理稿几乎无约束：真伪检查只核对页数和标题；只查 md 有无结论，不查 pptx 是否画出；没有红色面积检查。
- process 说明折行难看但生成器没有警告。
- ppt-review 清单第 6 条与第 1 条在问题页 `!` 上冲突，需要明确优先级。

## 第 3 轮：方向 C 落地后重跑（2026-10-15，spec #47 实现后）

- 打磨：沿用定稿简报，只按新规则（lead 必须是结论）重审各页 lead。第 4 页原 lead「6 月、9 月作业量相近，前后可比」是口径限定，改为「改善来自排班，不是业务变少：两月作业量相近，等待少 27 分钟」，「作业量相近」挪进口径行，口径表补「等待少 27 分钟」一行；其余 5 页不变。简报列名改为「lead / Next」。
- 生成 + 审核：
  - 第 1 轮：`[流程说明折行]` 第 2 页第 4 步「班组长每天查前一天执行率」末行剩「行率」→ 改为「班组长早会查昨日执行率」；
  - 第 2 轮：仍折行（末行剩「率」）→ 改为「早会查昨日执行率」，`REVIEW OK`。两处改动同步进简报。
- 成稿：`deck.pptx`（第 2 轮成稿保留为 `deck-round2.pptx`）。
- 自查发现（待人审一并判断）：

  - stats 解读没有折行检查：第 4 页「司机按推送时段到点充电」末行只剩「电」。
  - timeline、stats-side 右栏下方仍有空白。
