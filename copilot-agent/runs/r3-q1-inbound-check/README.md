# 第一次手工测试：只有指令、没有知识库

在公司电脑的 Copilot Chat 里，用同一道题开 5 个新对话，看回答格式对不对、5 次之间稳不稳定。不建 agent，不上传任何文件。全部素材都是虚构的。

## 文件夹里有什么

| 文件 | 用途 |
| --- | --- |
| `README.md` | 本说明：步骤 + 记录表 |
| `1-先发-指令.txt` | 每个对话的**第一条消息**：整份复制，原样粘贴发送 |
| `2-再发-题目.txt` | 每个对话的**第二条消息**：整份复制，原样粘贴发送 |
| `01.md` … `05.md` | 空文件，分别存第 1–5 次的回答 |

## 准备（只做一次）

1. 在公司电脑上拉取最新版：`git pull`（分支 `copilot-agent`）。
2. 打开 Copilot Chat（浏览器或 Teams 里都行，5 次都用同一个入口），确认登录的是公司账号。

## 每次测试的步骤（共做 5 次，第 N 次存进 `0N.md`）

1. **开新对话**：点「新建聊天」。每次都要新开，不能在上一次的对话里接着问。
2. **发指令**：打开 `1-先发-指令.txt`，全选、复制，粘贴到 Copilot 输入框，发送。
3. **等它回复**：一般会说"请提供材料"之类的话，不用管内容。
4. **发题目**：打开 `2-再发-题目.txt`，全选、复制，粘贴，发送。
5. **等它写完**：回答里会有一个标题为「Markdown」的卡片，等卡片完整出来、不再滚动。
6. **复制文稿**：点 Markdown 卡片**右上角的复制按钮**（两个方块叠在一起的图标）。不要全选整段回答复制。
7. **存文件**：打开 `0N.md`，粘贴。然后看一下：
   - 第一行是 ```` ```markdown ```` 或 ```` ``` ````：不用改。
   - 第一行是 `---`：在最前面加一行 ```` ```markdown ````，在最后面加一行 ```` ``` ````。
8. **补卡片外的文字**：卡片下面如果有"需要补充的数据"之类的说明，复制下来，粘贴在 `0N.md` 最后（代码块外面）。
9. **填记录表**：在下面的表里填这一次的情况。

5 次都做完后：保存全部文件，`git add`、`git commit`、`git push`，告诉我一声，我来跑评测。

## 注意

- 只粘贴这两个文件里的内容，不要改写，也不要加别的话。
- 回答里如果出现了公司真实信息（理论上不会），这一份不要提交，在记录表里注明。
