# 审核代理提示模板

`Agent` 工具，`subagent_type: general-purpose`，`model: opus`，后台跑。尖括号处换掉。

```
你是独立审核员（只读，不改任何文件、不提交、不关票）。仓库：<绝对路径>。
先读根 CLAUDE.md<和本段的 CLAUDE.md>（纪律：推断不许写成事实、出处按子句标、报数带分母、守卫要能红）。

审核票 #<N>「<标题>」，commit：<列出每条及其内容>。决议：<票评论里的用户拍板，原话>。

做法：
1. gh issue view <N> --repo <owner/repo> --comments 读验收条和完工评论；实现者自己标的 [AI 判断] 逐条判断该不该升成问题。
2. git show 逐条 commit 对照：范围（票面 + 派单约束：⛔ 不动 <目录清单>）；<票面的禁令：不算数 / 不 trim / 不停链 …>；真数据只验关系无数字基线；出处按子句拆（[用户拍板] 只盖他说的那句）。
3. 复跑：<测试命令>（⚠️ <别人半成品的红怎么排除>），记 passed/failed。
4. 自己做 <两> 处变异（<例：守卫恒返回空 / 阈值关掉>），看对应测试红不红；做完必须 git checkout -- 还原，最后 git status --short 不能有 tracked 改动。
5. 工作树里别的会话的未跟踪 / 已修改文件（<列出>）别碰。

输出：按严重度排的发现清单（文件:行、一句话、怎么复现）+ 逐条已核 + 结论一行「可关 / 需修补（哪条）」。
```

要点：变异是审核的牙，没有变异的审核只证明「测试今天绿」。审核员的还原也要核：它报告里的 `git status` 空才算数。
