# 项目汇报模式规则（§1–§3）

只在项目汇报模式（文稿 frontmatter 写了 `report: project`）读本文件；何时开这个模式见 SKILL.md「适用范围」B 类。文中 §4–§9 指 SKILL.md 的对应章节；§3 的「月报例外」也在 SKILL.md。

## 1. 固定 Agenda 顺序（不可改、不可去节）

> ⚠️ **本节属于 B 类规则，仅项目汇报模式（`report: project`）生效。** 展会汇报、培训分享等场景跳过本节，按内容自然组织章节。

| #   | 章节               | 英文(固定)   | PDCA         | 这一节要回答什么                                                 |
| --- | ------------------ | ------------ | ------------ | ---------------------------------------------------------------- |
| 01  | 项目背景           | `BACKGROUND` | `[PLAN]`     | 为什么做、痛点是什么                                             |
| 02  | 项目目标           | `TARGET`     | `[PLAN]`     | 目标是什么、要解决什么                                           |
| 03  | 项目范围           | `SCOPE`      | `[PLAN]`     | 边界，包含什么、不包含什么                                       |
| 04  | 项目应用场景       | `USE CASES`  | `[PLAN]`     | 在哪些场景落地                                                   |
| 05  | 项目节点           | `MILESTONE`  | `[DO]`       | 时间线、关键 milestone                                           |
| 06  | 项目行动与成果     | `OUTCOMES`   | `[DO/CHECK]` | **已完成的工作**和**已拿到的结果** —— 禁止写"将要 / 计划 / 未来" |
| 07  | 项目团队           | `TEAM`       | —            | 谁参与、分工（生成器版式 `team`）                                 |
| 08  | 持续优化与经验沉淀 | `LESSONS`    | `[ACT]`      | **上线后已落地的迭代**和经验沉淀 —— 禁止写未来 roadmap           |

**英文标题为强制项,不可改写**(例如不能把 `TARGET` 改成 `OBJECTIVES`、`MILESTONE` 改成 `TIMELINE`、`USE CASES` 改成 `SCENARIOS`)。
统一英文有两个作用:(1) 跨项目汇报视觉一致;(2) 听众扫一眼英文就知道这是 Agenda 第几节,不需要重新理解。

子节点英文标题自由(例如 06.2 可以叫 `GATEWAY` 或 `MIGRATION`),只要从属于父节即可。

可加子节点（如 `06.1 报表上线明细`、`06.2 用户反馈`），但：

- 不可改 8 节顺序
- 不可删除任意一节
- 子节点必须从属于父节，不可独立成章

## 2. PDCA 思维 — 每节都要标注阶段

> ⚠️ **本节属于 B 类规则，仅项目汇报模式（`report: project`）生效。** 其他场景不加 PDCA 图标。

**位置固定**：PDCA 标签放在**banner 下沿与正文区上沿之间（1.02–1.30"）的右侧窄带**（右缘贴正文区右缘），不要写进红 banner 的副标题里。
生成器写法：该页写一行 `PDCA: D`（组合 `PDCA: D/C` 按写的顺序从左到右排）。图标 0.28" 见方，放在 banner 下沿和正文区上沿之间（1.02–1.30"），右缘贴正文区右缘，不压任何版式的内容；同页写了 `Tag:` 时月份标识让到图标左侧、与图标纵向居中对齐。
标签值固定为 `P` / `D` / `C` / `A`，与上表对应。两个特例：

- 第 06 节标注 `[DO/CHECK]`：讲"做了什么"的页用 `D` 图标，讲"结果验证 / 数据核对"的页用 `C` 图标，一页只放一个
- 第 07 节"项目团队"不带 PDCA 标签

## 3. "已落地 vs 未来" 严格分离 — 强制规则

> ⚠️ **本节属于 B 类规则，仅项目汇报模式（`report: project`）生效。** 展会汇报、培训分享等场景**允许**写后续建议 / 行动项 / Next Step。

这是用户明确的强制规则（项目汇报场景下），违反会被驳回。

- **第 06 节"项目行动与成果"** = 已完成的工作 + 已拿到的结果
- **第 08 节"持续优化与经验沉淀"** = 上线后已落地的迭代和经验
- **整篇汇报不写**：未来规划 / Next Step / Roadmap / "下一步要做什么" / 画饼
