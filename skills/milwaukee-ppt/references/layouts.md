# 生成器版式参考

把文稿整理成生成器能读的 md 时读本文件：每个版式怎么写、什么时候选、什么时候别选、生成器会报什么错和警告。完整示例见 `examples/demo/deck.md`（6 个版式各一页）。Before/After 的槽位几何与事实对比验收另见 `before-after.md`。

## 文稿格式

```markdown
---
title: 工具借还线上化 项目汇报      # 写了 title = 通用模式
subtitle: 一行副标题                # 可选
author: 示例改进小组                # 可选
date: 13 Oct 2026                   # 可选；其中的 4 位年份用于给 Tag 补年份
closing: Thank You                  # 可选；不写就没有收尾页
---

# 主标题（banner 右上，填 idx 0）
## action title（填 idx 10）
Layout: process                    # 不写 = evidence；不区分大小写
Tag: Oct                           # 可选；正文区右上角灰字，没写年份时补上文稿年份
（本版式的字段，见下文）
普通文字行                          # 一句话结论，进底部红条
Next: 已确定的下一步                # 可选；写成「下一步：」时红条也显示「下一步」
```

- 每个 `# ` 开一页；第一个 `# ` 之前的内容和 `<!-- -->` 注释都会被忽略。
- 封面：主标题 = title；副标题第一行 subtitle，第二行「date   author」，空的省略。
- 月报模式：frontmatter 不写 title、写 `month: YYYY-MM` + `author`（`date` 可选）。封面固定为「<Mon>. YYYY Working Summary」，结尾固定加 Thank You，Tag 年份取 month。旧月报 md 不用改。
- 图片写 `![](路径)`：相对路径（相对文稿所在目录）、绝对路径、http(s) URL 都行。URL 下载后缓存在 `~/.cache/milwaukee-ppt/url-images`（环境变量 `MILWAUKEE_PPT_CACHE` 可改），之后离线也能重复生成。
- 输出：`-o` 指定；不指定时通用模式为 `<title>.pptx`，月报模式为 `Monthly Working Summary_<author>_<Mon>_<YYYY>.pptx`，都放在文稿所在目录。

## 报错与警告

**报错**：以非零退出，不留半坏的文件；除 frontmatter 外，信息都带 `页「标题」`。

- frontmatter 缺必填项（通用模式缺 title；月报模式缺 month / author，或 month 不是 YYYY-MM）
- 文稿里没有任何 `# ` 页
- `Layout:` 写了未知名字
- 条目数超出该版式范围，或条目格式不对（各版式小节里列出）
- 图片不存在、URL 下载失败

**警告**：打印 `警告: …` 到 stderr，照常生成。看到警告就去 PNG 里看对应那页，按提示精简文字。

- 文字估计溢出：红条、流程卡片、时间线列、Before/After 的短文、caption、lead、结论条
- 数据页大数字放不下，整页统一缩小
- 图多于版式能用的张数（多出的不用）、image-text 要点超过 5 条

## 共用排版（各版式统一，生成器写死）

内容区在 banner（0–1.0"）以下：上沿 1.30"，下沿 5.60"；左右边距 0.56"。块间距统一 0.3"，卡片内边距 0.2"。

| 用途 | 字号与样式（Arial；中文 PingFang SC） |
| --- | --- |
| 数据大数字 | 60pt bold，重点那个 #DB011C，其余 #1A1A1A |
| 条目标题 | 18pt bold #1A1A1A |
| 正文 / 要点 | 16pt #1A1A1A |
| 说明 | 14pt #6B6B6B |
| 小标签 / 日期 | 12pt bold #6B6B6B（全套最小字号） |
| 流程序号圆 | 直径 0.5"，#333333 底，白字 16pt bold |
| 底部红条 | 14pt 白字 |

**底部红条**（evidence、process、stats、timeline、image-text 共用）：月报模板固定样式——品牌红底、0.75pt 黑描边、白字 ❖ 项目符号、行距 150%。底边固定在 7.08"，最低 1.2" 高；文字多时向上加高，最高顶到 5.60"（内容区下沿），再多就警告。结论一行、Next 一行最合适。Before/After 用自己的单行结论条，见该小节。

**红色**：banner 以外只有三处用品牌红——底部红条 / 结论条、数据页标了 `!` 的那个数字、Before/After 的 AFTER 标题。流程序号圆、时间线节点一律黑白灰。

## evidence（默认）· 证据页

模板 layout 0。月报主力版式：截图或实物证据为主体 + 底部红条。

```markdown
# 项目背景 / BACKGROUND
## 纸质登记让借还记录难以追溯
![](img/paper-log.png)
抽查 3 个月的登记本，约三成借出记录没有归还登记
Next: 10 月底前完成全部工具贴码
```

- 字段：0–3 张图。图在内容区（0.56 / 1.30 / 12.2 / 4.3"）里横排，各自保持比例、不裁切；多张图宽高比差别大时按比例分宽度（需要 Pillow，没有就等分）。
- 适用：一个工作项的证据——系统界面、文档、表格、现场照片。
- 反例：只有文字没有证据，改用 process / stats / image-text；4 张以上图塞一页，拆页。
- 警告：图超过 3 张（只用前 3 张）；红条文字顶到 5.60"。

## before-after · 改前改后对比

模板 layout 3。槽位几何、填写顺序和事实对应的验收规则见 `before-after.md`。

```markdown
# 借还登记 / BEFORE-AFTER
## 登记从手写改为扫码，记录自动留存
Layout: before-after
同一试点车间、同一批工具，改前改后各统计 4 周

### Before: 纸质登记
![](img/paper-log.png)
Caption: 借出时手写登记，归还靠自觉补记

### After: 扫码登记
![](img/online-form.png)
Caption: 扫码自动带出工具信息，归还时扫码闭环

试点 4 周内借还记录全部可追溯
```

- 字段：
  - 第一个 `###` 之前的普通文字 = lead（正文顶部一行，20pt bold）；
  - `### Before` / `### After` 各一节，标题可写成 `### Before: 自定义标题`（不写显示 BEFORE / AFTER）；每节一张图或一段短文，再加一行 `Caption:`（可省）；
  - 最后一节之后的普通文字 = 底部结论，`Next:` 也进结论条。
- 结论条：caption 之下（顶边 6.43"）的品牌红窄条，白字 24pt，一行；有 Next 时第二行，顶边不动向下长，最低到 7.22"，离页脚很近，两行时生成后要看一眼。
- 适用：同一件事改前、改后的对应事实（流程、系统、现场）。
- 反例：两侧对象、时间窗口或统计口径不同；只有改后没有改前；BEFORE 写成贬低旧方案的话。
- 报错：缺 `### Before` 或 `### After`、小节名不是这两个、同一节写两次、某节没有内容、一节里既有图又有短文或有两张图、两节之间夹了普通文字。
- 警告：caption 超过两行；短文溢出内容区；lead 超过一行；结论或 Next 超过一行。

## process · 流程

模板 layout 4，槽位 idx 17（0.56 / 1.30 / 12.21 / 4.30"）。

```markdown
Layout: process
1. 贴码 | 每件工具贴唯一二维码
2. 扫码借出 | 扫码自动带出工具信息
3. 到期提醒 | 到期前一天推送提醒
```

- 字段：3–5 条有序列表「步骤名 | 一句说明」，说明可省；序号写 `1.` `1)` `1、` 都行。
- 画法：等宽卡片（#F5F5F5 底、#E5E5E5 细描边），间距 0.3"；序号圆压在卡片上沿、靠左；不画箭头。卡片等高、最低 2.0"，整组在槽位里垂直居中。
- 适用：有先后顺序的 3–5 个步骤。
- 反例：步骤之间没有顺序（并列要点用 image-text 或拆页）；6 步以上（合并步骤或拆两页）；说明写成一段话。卡片宽度下说明每行约 12 个汉字（4 步时），写到两行以内。
- 报错：步骤少于 3 或多于 5。
- 警告：某步的说明估计溢出卡片。

## stats · 数据对比 / Key Results

模板 layout 5，槽位 idx 18（0.56 / 1.30 / 12.21 / 4.30"）。

```markdown
Layout: stats
- 试点工具 | 120 件 | 覆盖试点车间全部手持工具
- !记录完整率 | 100% | 改前约 70%，抽查口径相同
- 单次登记用时 | 15 秒 | 改前手写约 1 分钟
```

- 字段：2–4 条无序列表「标签 | 数字 | 一句说明」，三段都必填；最多一条在列表符号后加 `!`，它的数字用品牌红。
- 画法：等宽数据卡（#F5F5F5 底、无描边），卡内自上而下：12pt 小标签、60pt 大数字、14pt 说明。
- **大数字尽量写短（如 12.3M）；放不下时整页统一缩小并警告**：所有数字共用一个字号，按最长那个缩，最低 28pt。
- 适用：2–4 个能并排比较的结果数字。
- 反例：数字没有出处或口径不一致；把每个数字都标红（只能一个 `!`）；一个数字配一大段解释（改用 evidence 配证据）。
- 报错：条目少于 2 或多于 4；某条不是三段或有空段；`!` 多于一条。
- 警告：大数字统一缩小（缩到 28pt 仍放不下时另有提示）。

## timeline · 时间线

模板 layout 6，槽位 idx 19（0.56 / 1.30 / 12.21 / 4.30"）。

```markdown
Layout: timeline
- 07 Jul | 立项 | 确定试点车间与工具范围
- 04 Aug | 表单上线 | 扫码借还表单开放试用
- 25 Aug | 贴码完成 |
```

- 字段：3–6 条无序列表「日期 | 标题 | 说明」；日期和标题必填，说明可空，但两个 `|` 都要写。
- 画法：一条 #BFBFBF 横线，节点等距（直径 0.24" 的 #333333 圆）；日期在线上方（12pt bold 灰），标题（18pt bold）和说明（14pt 灰）在线下方，都与节点居中。
- 适用：里程碑、阶段节点。
- 反例：节点超过 6 个（合并或拆页）；用时间线讲没有时间顺序的事；说明写成长句（6 个节点时每列约 1.8" 宽）。
- 报错：条目少于 3 或多于 6；某条不是三段，或日期 / 标题为空。
- 警告：某条的日期、标题或说明估计溢出。

## image-text · 左图右文

模板 layout 7：左图框 idx 20（0.56 / 1.30 / 7.64 / 4.30"，16:9），右文字槽 idx 21（8.50 / 1.30 / 4.27 / 4.30"）。

```markdown
Layout: image-text
![](img/dashboard.png)
- 按车间显示在借、逾期、闲置数量
- 逾期数量单独标红，点开可见借用人
```

- 字段：一张图 + 若干条无序列表要点（≤5 条）。
- 画法：图在图框里等比缩放、完整显示、不裁切，横竖都居中；要点用文字槽自带样式（16pt、灰色圆点）。没有要点时文字槽删掉。
- 适用：一张系统截图或照片 + 几条解释。
- 反例：两张以上图（用 evidence）；要点写成段落；只有文字没有图。
- 报错：没有图；图片不存在。
- 警告：图多于一张（只用第一张）；要点超过 5 条。

## 选版速查

| 内容 | 版式 |
| --- | --- |
| 一个工作项的截图 / 实物证据 | evidence |
| 同一件事改前、改后 | before-after |
| 3–5 个有先后的步骤 | process |
| 2–4 个结果数字 | stats |
| 3–6 个时间节点 | timeline |
| 一张图 + 几条解释 | image-text |
| 都不匹配（Agenda、团队、表格等） | 生成器没有对应版式；先用最接近的生成，再在 PowerPoint 里按 SKILL.md §6 和 `layout-patterns.md` 手工调整 |
