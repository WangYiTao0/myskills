# 生成器版式参考

把文稿整理成生成器能读的 md 时读本文件：每个版式怎么写、什么时候选、什么时候别选、生成器会报什么错和警告。完整示例见 `examples/demo/deck.md`（evidence 到 image-text 8 个版式各一页；section 的写法见本文件对应小节）。生成后要按形状改细节时，形状名见文末「形状命名约定」。Before/After 的槽位几何与事实对比验收另见 `before-after.md`。

## 文稿格式

下面的代码块可以照抄生成（代码块里不能写行尾注释，生成器会把它当成内容），各行的含义写在块后。

```markdown
---
title: 工具借还线上化 项目汇报
subtitle: 示例文稿 · 虚构数据
author: 示例改进小组
date: 13 Oct 2026
closing: Thank You
---

# 项目背景 / BACKGROUND
## 纸质登记让借还记录难以追溯
Layout: evidence
Tag: Oct
![](img/paper-log.png)
抽查 3 个月的登记本，约三成借出记录没有归还登记
Next: 10 月底前完成全部工具贴码
```

- frontmatter：写了 `title` = 通用模式；`subtitle`、`author`、`date`、`closing` 都可选。`date` 里的 4 位年份用于给 Tag 补年份；不写 `closing` 就没有收尾页。
- `# ` 是主标题（banner 右上，填 idx 0），`## ` 是 action title（填 idx 10）。
- `Layout:` 选版式，不写 = evidence，不区分大小写。
- `Tag:` 可选，正文区右上角灰字；没写年份时补上文稿年份。
- 版式字段（上例是 evidence 的图）见下文各小节。
- 普通文字行是一句话结论，进底部红条。
- `Next:` 可选，写已确定的下一步；写成「下一步：」时红条也显示「下一步」。
- 每个 `# ` 开一页；第一个 `# ` 之前的内容和 `<!-- -->` 注释都会被忽略。
- 封面：主标题 = title；副标题第一行 subtitle，第二行「date   author」，空的省略。
- 月报模式：frontmatter 不写 title、写 `month: YYYY-MM` + `author`（`date` 可选）。封面固定为「<Mon>. YYYY Working Summary」，结尾固定加 Thank You，Tag 年份取 month。旧月报 md 不用改。
- 图片写 `![](路径)`：相对路径（相对文稿所在目录）、绝对路径、http(s) URL 都行。URL 下载后缓存在 `~/.cache/milwaukee-ppt/url-images`（环境变量 `MILWAUKEE_PPT_CACHE` 可改），之后离线也能重复生成。
- 输出：`-o` 指定；不指定时通用模式为 `<title>.pptx`，月报模式为 `Monthly Working Summary_<author>_<Mon>_<YYYY>.pptx`，都放在文稿所在目录。

## 报错与警告

**报错**：以非零退出，不留半坏的文件。出在某一页的错误（版式名、条目、图片），信息里带 `页「标题」`；整份文稿的错误（输入文件找不到、frontmatter、没有任何页、输出路径）不带页标题。

- frontmatter 缺必填项（通用模式缺 title；月报模式缺 month / author，或 month 不是 YYYY-MM）
- 文稿里没有任何 `# ` 页
- `Layout:` 写了未知名字
- 条目数超出该版式范围，或条目格式不对（各版式小节里列出）
- 时间线状态写错、只写了一部分、“进行中”多于一个（见 timeline 小节）
- 图片不存在、URL 下载失败

**警告**：打印 `警告: …` 到 stderr，照常生成。看到警告就去 PNG 里看对应那页，按提示精简文字。

- 文字估计溢出：红条、流程卡片、数据页的解读 / 卡片文字 / 结论要点 / 口径、时间线列、阶段条、Before/After 的短文、caption（超过一行）、lead（超过一行）
- 数据页大数字放不下，整页统一缩小
- 图多于版式能用的张数（多出的不用）、image-text 要点超过 5 条

## 共用排版（各版式统一，生成器写死）

内容区在 banner（0–1.0"）以下：上沿 1.30"，下沿 5.60"；左右边距 0.56"。块间距统一 0.3"，卡片内边距 0.2"。

| 用途 | 字号与样式（Arial；中文 PingFang SC） |
| --- | --- |
| 数据大数字 | 60pt bold，重点那个 #DB011C，其余 #1A1A1A；单位（件、%、秒…）自动拆出，28pt #6B6B6B 不加粗、同一基线 |
| 数据标签 | 16pt bold #1A1A1A |
| 条目标题 | 18pt bold #1A1A1A（时间线普通节点 16pt） |
| 正文 / 要点 | 16pt #1A1A1A（stats 的解读 14pt） |
| 说明 | 14pt #6B6B6B |
| 日期 / 口径 / 图例 | 12pt #6B6B6B，日期加粗（全套最小字号） |
| 流程序号圆 | 直径 0.5"，#333333 底，白字 16pt bold |
| 底部红条 | 14pt 白字 |

**底部红条**（各版式共用）：月报模板固定样式——品牌红底、0.75pt 黑描边、白字 ❖ 项目符号、行距 150%。底边固定在 7.08"，最低 1.2" 高；文字多时向上加高，最高顶到 5.60"（内容区下沿），再多就警告。结论一行、Next 一行最合适。

**红色**：banner 以外只有这几处用品牌红——底部红条、数据页标了 `!` 的那条（数字 + stats 的顶线 / stats-side 的竖条）、Before/After 的 AFTER 标题。流程序号圆一律黑白灰。时间线类版式写了状态时用状态色（SKILL.md §6.3「时间线状态色」例外）：已完成 #2E7D32、进行中 #F2A900（上面的字 #1A1A1A）、未完成用品牌红但只描边或空心；不写状态的时间线仍是黑白灰。

## evidence（默认）· 证据页

模板 layout 0。月报主力版式：截图或实物证据为主体 + 底部红条。

```markdown
# 项目背景 / BACKGROUND
## 纸质登记让借还记录难以追溯
![](img/paper-log.png)
抽查 3 个月的登记本，约三成借出记录没有归还登记
Next: 10 月底前完成全部工具贴码
```

- 字段：0–3 张图。图在内容区（0.56 / 1.30 / 12.2 / 4.3"）里横排，各自保持比例、不裁切；多张图宽高比差别大时按比例分宽度（需要 Pillow，没有就等分）。
- 适用：一个工作项的证据——系统界面、文档、表格、现场照片。
- 反例：只有文字没有证据，改用 process / stats / image-text；4 张以上图塞一页，拆页。
- 警告：图超过 3 张（只用前 3 张）；红条文字顶到 5.60"。

## before-after · 改前改后对比

模板 layout 3。槽位几何、填写顺序和事实对应的验收规则见 `before-after.md`。

```markdown
# 借还登记 / BEFORE-AFTER
## 登记从手写改为扫码，记录自动留存
Layout: before-after
同一试点车间、同一批工具，改前改后各统计 4 周

### Before: 纸质登记
![](img/paper-log.png)
Caption: 借出时手写登记，归还靠自觉补记

### After: 扫码登记
![](img/online-form.png)
Caption: 扫码自动带出工具信息，归还时扫码登记

试点 4 周内借还记录全部可追溯
```

- 字段：
  - 第一个 `###` 之前的普通文字 = lead（正文顶部一行，20pt bold）；
  - `### Before` / `### After` 各一节，标题可写成 `### Before: 自定义标题`（不写显示 BEFORE / AFTER）；每节一张图或一段短文，再加一行 `Caption:`（可省）；
  - 最后一节之后的普通文字 = 底部结论，和 `Next:` 一起进底部红条（与其他版式同一种红条）。
- 画法：标题进 idx 11/12，图或短文进对比框里的 13/14（图等比缩放、居中，短文在框宽内换行），caption 进 15/16（16pt bold，一行）。没有红条时 caption 在框下 6.12"；有红条时红条会盖住那里，生成器把 caption 挪进对比框底部（5.20–5.55"），内容区缩到它上方；对比框底边被红条盖住约 0.04"，属正常。lead 在 0.56 / 1.30"，写了 Tag 时右端让开月份标识。
- 适用：同一件事改前、改后的对应事实（流程、系统、现场）。
- 反例：两侧对象、时间窗口或统计口径不同；只有改后没有改前；BEFORE 写成贬低旧方案的话。
- 报错：缺 `### Before` 或 `### After`、小节名不是这两个、同一节写两次、某节没有内容、一节里既有图又有短文或有两张图、两节之间夹了普通文字。
- 警告：caption 超过一行；短文溢出内容区；lead 超过一行；红条文字顶到 5.60"。

## process · 流程

模板 layout 4，槽位 idx 17（0.56 / 1.30 / 12.21 / 4.30"）。

```markdown
Layout: process
1. 贴码 | 每件工具贴唯一二维码
2. 扫码借出 | 扫码自动带出工具信息
3. 到期提醒 | 到期前一天推送提醒
```

- 字段：3–5 条有序列表「步骤名 | 一句说明」，说明可省；序号写 `1.` `1)` `1、` 都行。
- 画法：等宽卡片（#F5F5F5 底、#E5E5E5 细描边），间距 0.3"；序号圆压在卡片上沿、靠左；不画箭头。卡片等高、最低 2.0"，整组在槽位里垂直居中。
- 适用：有先后顺序的 3–5 个步骤。
- 反例：步骤之间没有顺序（并列要点用 image-text 或拆页）；6 步以上（合并步骤或拆两页）；说明写成一段话。卡片宽度下说明每行约 12 个汉字（4 步时），写到两行以内。
- 报错：步骤少于 3 或多于 5。
- 警告：某步的说明估计溢出卡片。

## stats · 数据对比 / Key Results

模板 layout 5，槽位 idx 18（0.56 / 1.30 / 12.21 / 4.30"）。分栏式：每个数字一栏，数字下面跟它自己的解读。

```markdown
Layout: stats
- 试点工具 | 120 件 | 覆盖试点车间全部手持工具
  - 电动工具 86 件、量具 34 件
  - 贴码 8 月 25 日完成，比计划晚一周
- !记录完整率 | 100% | 改前约 70%，抽查口径相同
  - 4 周借还 1,240 次，全部有归还记录
  - 逾期未还从每周约 9 件降到 2 件
- 单次登记用时 | 15 秒 | 改前手写约 1 分钟
  - 扫码自动带出工具信息，不用手写编号
口径：改前取 6–8 月登记本抽查，改后取系统导出，同一车间同一批工具
试点 4 周借还记录完整率 100%，单次登记用时降到 15 秒
```

- 字段：
  - 卡片：2–4 条无序列表「标签 | 数字 | 一句说明」，三段都必填；最多一条在列表符号后加 `!`，标为重点（只写一个 `!`，`!!` 报错）。
  - 解读：写在卡片行下面、缩进的 `- `，是这张卡自己的解读，每张最多 3 条，可以不写。
  - 口径：`口径：` 或 `Source:` 开头的一行，可选。
  - 其余普通文字行进底部红条。
- 画法：槽位等分成 n 栏（栏间距 0.45"），每栏自上而下：顶部粗线（重点栏品牌红，其余 #1A1A1A）、16pt bold 标签、60pt 大数字（重点那个品牌红）、14pt 灰说明；有解读时再画一条 #E5E5E5 细分隔线和 14pt 带圆点的解读。口径是 12pt 灰字，通栏贴在内容区底部。
- 单位自动拆：数字字段里的数值（含 `$` `+` `-`、千分位逗号、小数点）按大数字显示；数量级后缀（`12.3M`、`5x`）、`+`（`1,000+`）、`/数字`（`24/7`、`3/5`）也算大数字。后面的 `%`、中文单位、空格后的英文单位（`5 d`）缩成 28pt 灰字；数字前的 `约` `~` `≈` `≥` `≤` `>` `<` `+/-` 也缩成同样的灰色小字。数字和单位之间的空格照原文，不自动补：`120 件`、`120件`、`100%`、`约 5 天`、`≥95%` 都照写。整串不以（前缀 +）数字开头时（如 `Q3`、`N/A`）按大数字原样显示。
- **大数字尽量写短（如 12.3M）；放不下时整页统一缩小并警告**：所有数字共用一个字号，按最紧的那个缩，最低 28pt。
- 旧写法：整页一条解读都不写时，只画顶线、标签、数字、说明，这一组在口径以上的区域里上下居中，不画分隔线；不报错。
- 适用：2–4 个能并排比较的结果数字，每个数字需要一两句话说明它意味着什么。
- 反例：
  - 数字没有出处或口径不一致；
  - 把每个数字都标红（只能一个 `!`）；
  - 一个数字配一大段解释（改用 evidence 配证据）；
  - 结论比数字重要、结论是针对整组数字的（改用 stats-side）。
- 报错：
  - 卡片少于 2 或多于 4；某条不是三段或有空段；`!` 多于一条；
  - 以 `!` 开头、含 `|` 却漏写列表符号的行（应写成 `- !…`）；写成 `- !!…`；
  - 第一张卡片之前就写了缩进的解读；某张卡的解读多于 3 条；
  - 口径多于一行。
- 警告：大数字统一缩小（缩到 28pt 仍放不下时另有提示）；某张卡的解读估计放不下；口径超过一行。

## stats-side · 左数字右结论

模板 layout 5，槽位 idx 18。左边竖排横卡，右边带编号的结论区；页面的重心在结论。

```markdown
Layout: stats-side
- 试点工具 | 120 件 | 覆盖试点车间全部手持工具
- !记录完整率 | 100% | 改前约 70%
- 单次登记用时 | 15 秒 | 改前手写约 1 分钟
### 试点结论
> 记录完整率达到 100%，抽查不再缺页
> 逾期提醒起作用，逾期件数明显下降
> 登记用时下降主要来自扫码自动带出信息
口径：改前取 6–8 月登记本抽查，改后取系统导出
记录完整率和登记用时都达到推广条件
```

- 字段：
  - 卡片：2–3 条「标签 | 数字 | 一句说明」，写法和 stats 相同，最多一条 `!`；卡片不带缩进解读。
  - 结论区小标题：`### 小标题`，可选，不写显示「结论」。
  - 结论要点：1–4 条 `> ` 开头的行，生成时自动编号，不用手写序号。
  - 口径：`口径：` 或 `Source:` 开头的一行，可选。
  - 其余普通文字行进底部红条。
- 画法：左侧 6.0" 宽一列 #F5F5F5 底横卡，卡片等高撑满槽位、间距 0.3"；卡内左边大数字（60pt，单位同 stats 自动拆成 28pt 灰字），右边 16pt bold 标签 + 14pt 灰说明。重点卡左边一条品牌红竖条，数字也是品牌红。右侧结论区：18pt bold 小标题、#E5E5E5 细分隔线、16pt 编号要点（编号灰色）；口径 12pt 灰字贴结论区底部。
- 大数字放不下时整页统一缩小，最低 36pt。
- 适用：2–3 个数字撑起一组结论，听众要记住的是结论；写成 stats 时解读会在各栏重复同一句话。
- 反例：
  - 每个数字各有自己的解读（用 stats）；
  - 4 个以上数字（用 stats 或拆页）；
  - 结论要点写成段落，或超过 4 条。
- 报错：
  - 卡片少于 2 或多于 3；卡片格式同 stats 的要求；`!` 多于一条；漏写列表符号的 `!` 行；
  - 卡片下面写了缩进的 `- ` 解读（改写成 `> ` 结论要点，或改用 stats）；
  - 没有 `> ` 结论要点，或多于 4 条；
  - 口径多于一行；`###` 小标题多于一个。
- 警告：大数字统一缩小；某张卡的标签和说明估计放不下；结论要点估计放不下；口径超过两行。

## timeline · 时间线

模板 layout 6，槽位 idx 19（0.56 / 1.30 / 12.21 / 4.30"）。横线加节点，写了状态时按状态着色。

```markdown
Layout: timeline
- 07 Jul | 立项 | 确定车间与工具范围 | 完成
- !04 Aug | 表单上线 | 扫码表单开放试用 | 完成
- 25 Aug | 贴码完成 | 比计划晚一周 | 完成
- !15 Sep | 试点开始 | 切换为扫码登记 | 完成
- 13 Oct | 试点复盘 | 4 周数据汇总中 | 进行中
- !03 Nov | 推广二车间 | 二车间切换扫码 | 未完成
贴码晚一周未影响试点开始，试点复盘 10 月内完成
```

- 字段：3–6 条无序列表「[!]日期 | 标题 | 说明 | 状态」。
  - 日期和标题必填；说明可空，但它前后的 `|` 要写。
  - 状态（第 4 段）：完成 / 已完成 / 进行中 / 未完成，或 done / doing / todo，不区分大小写。一页里要么每条都写，要么都不写；“进行中”最多一个。
  - 列表符号后加 `!` = 关键里程碑，可以多条；每条只写一个 `!`，`!!` 报错。
- 画法（写了状态）：槽位等分成列（列间距 0.3"），节点在横线上、居中；日期在线上方，标题和说明在线下方。
  - 已完成：绿色实心圆带白对勾；首节点到进度终点（进行中那条，没有进行中时到最后一个已完成）是绿色粗线，之后是灰色虚线。
  - 进行中：放大的琥珀色圆 + 外圈，上方近黑“当前”标签，日期 14pt 加粗近黑。
  - 未完成：白底红描边空心，标题灰色。
  - 关键里程碑：放大的菱形，颜色按状态；标题 18pt（普通节点 16pt）。
  - 内容区右上角一行图例：已完成 / 进行中 / 未完成 / 关键里程碑；写了 `Tag:` 时图例下移让开月份标识。
- 画法（不写状态，旧写法）：保持黑白灰——一条 #BFBFBF 横线，直径 0.24" 的 #333333 圆节点，日期 12pt bold 灰、标题 18pt bold、说明 14pt 灰；带 `!` 时会画菱形（放大的深灰菱形）；没有图例。旧文稿不用改：不写状态也不写 `!` 时，画出来和加状态色之前完全一样。
- 适用：里程碑、阶段节点；要让人一眼看出走到哪一步时写状态。
- 反例：节点超过 6 个（合并或拆页）；用时间线讲没有时间顺序的事；说明写成长句（6 个节点时每列约 1.8" 宽）；每个节点都标 `!`（关键里程碑就分不出来了）。
- 报错：条目少于 3 或多于 6；某条不是三段或四段，或日期 / 标题为空；状态值不认识；只有部分条写了状态；“进行中”多于一个。报错信息带页标题，状态错误还带第几条。
- 警告：某条的日期、标题或说明估计溢出。

## timeline-phase · 阶段条

模板 layout 6，槽位 idx 19。同样的节点画成一排箭头段，表达“阶段推进”。

```markdown
Layout: timeline-phase
- Jul | 立项 | 确定车间与工具范围 | 完成
- Aug | 准备 | 表单上线、全部贴码 | 完成
- !Sep | 试点 | 试点车间切换扫码 | 完成
- Oct | 复盘 | 4 周数据汇总中 | 进行中
- !Nov | 推广 | 第二个车间切换扫码 | 未完成
复盘结论 10 月底前提交
```

- 字段：3–6 条「[!]日期 | 标题 | 说明 | 状态」，写法同 timeline，但**每条都必须写状态**；说明可空。`!` = 关键里程碑。
- 画法：槽位横向等分成 n 段箭头（首段平尾、其余带凹口），标题写在段内；日期在段上方；段下方细线连到标记，最下面是 14pt 灰说明。
  - 已完成：绿底白字。
  - 进行中：琥珀底深色字，这一段加高，标题和日期放大。
  - 未完成：浅粉底、红描边、红字。
  - 关键里程碑：标记是黑色菱形，下面标“关键里程碑”；普通节点是灰色小圆点。
  - 内容区右上角一行图例，图形是缩小的箭头段和菱形，始终显示 4 项。
- 适用：3–6 个前后衔接的阶段，强调整体推进到哪一段；标题要短（段内一行，6 段时约 7 个汉字）。
- 反例：节点是具体日期上的事件、不是持续一段时间的阶段（用 timeline）；还没定状态（用 timeline 的旧写法）；标题写成长句。
- 报错：条目少于 3 或多于 6；格式不对或日期 / 标题为空；有条目没写状态；状态值不认识；“进行中”多于一个。
- 警告：某条的标题放不进箭头段、日期超过一行或说明估计溢出。

## image-text · 左图右文

模板 layout 7：左图框 idx 20（0.56 / 1.30 / 7.64 / 4.30"，16:9），右文字槽 idx 21（8.50 / 1.30 / 4.27 / 4.30"）。

```markdown
Layout: image-text
![](img/dashboard.png)
- 按车间显示在借、逾期、闲置数量
- 逾期数量单独标红，点开可见借用人
```

- 字段：一张图 + 若干条无序列表要点（≤5 条）。
- 画法：图在图框里等比缩放、完整显示、不裁切，横竖都居中；要点用文字槽自带样式（16pt、灰色圆点）。没有要点时文字槽删掉。
- 适用：一张系统截图或照片 + 几条解释。
- 反例：两张以上图（用 evidence）；要点写成段落；只有文字没有图。
- 报错：没有图；图片不存在。
- 警告：图多于一张（只用第一张）；要点超过 5 条。

## section · 隔断页

模板 layout 0（和 evidence 共用；inspect 靠 `Section Number` 认出 section）。章节之间的过渡页：章节编号 + 中文名 + 英文名是页面主体。

```markdown
# 试点推进 / PILOT
## 试点 4 周，借还记录全部可追溯
Layout: section
02 | 试点推进 | PILOT
```

- 字段：正好一行「编号 | 中文名 | 英文名」，三段都必填。
- 容量：编号最多 3 字（`02`、`A`、`3.1`），中文名最多 12 字，英文名最多 40 字符。
- 主标题、副标题照常填 idx 0 / 10；副标题仍写一句结论（本章要点），不要只重复章节名。
- 不放结论红条：写普通文字行或 `Next:` 都报错。`Tag:` 照常可用。
- 画法：正文区里一组横排、整组垂直居中：左边 96pt bold #1A1A1A 编号，一条 #BFBFBF 竖线，右边 40pt bold #1A1A1A 中文名，下面 20pt #6B6B6B 英文名。只用黑白灰，不用红。
- 适用：页数较多、分了几个章节的汇报，在章节之间提示“下面进入第几部分”。
- 反例：总页数本来就少（≤ 6 页）或只有一两个章节，加隔断页只是凑页；两张隔断页连着放（中间那章没有内容）；把本章的结论、数字写进隔断页（放到该章的正文页）。
- 报错：没有编号行或多于一行；某行不是三段；某段为空；编号、中文名、英文名超过字数上限；写了普通文字结论行或 `Next:`。报错信息带页标题。
- 审核：`review_deck.py` 对 section 不报「缺结论行」（按设计没有红条）；「目录式副标题」照样检查。

## 选版速查

| 内容 | 版式 |
| --- | --- |
| 一个工作项的截图 / 实物证据 | evidence |
| 同一件事改前、改后 | before-after |
| 3–5 个有先后的步骤 | process |
| 2–4 个结果数字，每个数字跟几条解读 | stats |
| 2–3 个数字 + 一组结论，结论比数字重要 | stats-side |
| 3–6 个时间节点（带状态时看得出进度） | timeline |
| 3–6 个前后衔接的阶段，强调推进到哪一段 | timeline-phase |
| 一张图 + 几条解释 | image-text |
| 章节之间的过渡（编号 + 章节名） | section |
| 都不匹配（Agenda、团队、表格等） | 生成器没有对应版式；先用最接近的生成，再在 PowerPoint 里按 SKILL.md §6 和 `layout-patterns.md` 手工调整 |

## 形状命名约定

生成器给每个画出来的形状起固定的名字，生成后细调时按名字找元素（流程见 SKILL.md「生成后细调」）。`python3 scripts/inspect_ppt.py <输出.pptx>` 每页先给一行 `== 第 N 页 | layout: <模板 layout> | 版式: <生成器版式>`，再列出每个形状的名字、类型（占位框带 `idx=N`）、位置（英寸）和文字开头。

- 编号 N 从 1 起，和文稿里条目的顺序一致（左到右、上到下）。
- 名字是对 AI 的契约：版式改画法时，名字不变或同步改本节。
- 主标题、action title 是模板占位框，名字由 PowerPoint 决定，按 idx 0 / 10 找（`slide.placeholders[idx]`），不按名字找；inspect 输出里占位框的类型写成 `PLACEHOLDER idx=N`。

| 范围 | 形状名 |
| --- | --- |
| 各版式共用 | `Caption Bar`（底部红条）、`Month Tag`（`Tag:` 月份标识） |
| stats | `Stat Rule N`（顶部粗线）、`Stat Label N`、`Stat Number N`（前缀、数字、单位是同一段里的几个 run）、`Stat Note N`、`Stat Divider N`、`Stat Points N`（这张卡的全部解读，一条一段）、`Stat Source`（口径）；旧写法没有 Divider / Points |
| stats-side | `Side Card N`（卡片底）、`Side Accent N`（只有重点卡）、`Side Number N`、`Side Text N`（标签一段 + 说明一段）、`Side Conclusion Title`、`Side Conclusion Rule`、`Side Points`（全部结论要点，一条一段）、`Stat Source` |
| timeline（写了状态） | `Milestone Node N`、`Milestone Check N`（只在已完成节点上）、`Milestone Date N`、`Milestone Text N`（标题一段 + 说明一段）、`Progress Line`（绿色已完成段）、`Remaining Line`（灰色虚线）、`Current Ring`、`Current Tag`；图例 `Legend Icon 1–4`、`Legend Label 1–4`（1 已完成、2 进行中、3 未完成、4 关键里程碑）、`Legend Check 1`（已完成图标上的对勾） |
| timeline（不写状态） | `Timeline Line`、`Timeline Node N`、`Timeline Date N`、`Timeline Text N` |
| section | `Section Number`（章节编号，也是 inspect 区分 section / evidence 的标记形状）、`Section Rule`（竖线）、`Section Name`（中文名）、`Section English`（英文名） |
| timeline-phase | `Phase Segment N`（箭头段，标题在段内）、`Phase Date N`、`Phase Stem N`（细线）、`Phase Marker N`（菱形或小圆点）、`Phase Key Label N`（只有关键里程碑）、`Phase Text N`（说明）；图例 `Legend Icon 1–4`（缩小的箭头段 / 菱形）、`Legend Label 1–4`（编号同 timeline） |

其他版式的形状名（如 `Process Card N`、`Lead`）以 `inspect_ppt.py` 的输出为准。
